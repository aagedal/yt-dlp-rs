# Batch-file URL lists

Exact official source target and unchanged baseline:
`897341241f2bfb2439fe0367f4c7c9ccd29a3828` (2026.08.19). No intervening
upstream commits; the global baseline is unchanged.

Inspected `options.py` `-a/--batch-file` and `--no-batch-file` (1383–1392),
`__init__.py` `get_urls` (83–100) and its `parse_options` call (743), the
missing-URL `parser.error` (1063–1065), and `utils/_utils.py`
`read_batch_urls` (2574–2590), `expand_path` and `read_stdin`, plus
`test_utils.py` `test_read_batch_urls`. These mapped files also contain
`--load-info-json`, `-q`/`--verbose` debug output and the updater, which are
not implied by this slice.

Implemented: batch URLs precede positional URLs; bytes decode as UTF-8 with
invalid bytes dropped (`errors='ignore'`) and split on universal newlines
(`\r\n`, `\r`, `\n` only); each line drops a mis-decoded then a real BOM, is
left-stripped, skipped when empty or starting with `#`, `;` or `]`, cut at the
first whitespace-preceded `#` and right-stripped; positional URLs are stripped.
Whitespace follows Python `str.isspace` (including U+001C–U+001F). `-` reads
stdin after printing upstream's stderr prompt. Paths expand a leading `~`/`~/`
from `HOME` and `$NAME`/`${NAME}` ASCII-word variables, leaving unknown
variables. An unreadable file reports `batch file FILE could not be read` and
exits 1 before any request; no URLs at all report
`You must provide at least one URL.` The last of `--batch-file`/`--no-batch-file`
wins.

Native differences: `~user` and a missing `HOME` are not expanded; `-q` does not
exist, so the stdin prompt is always printed; the stdin stream uses the same
UTF-8 decoding instead of the locale encoding; no `--verbose` debug listing.

Ten saved cases in `tests/fixtures/batch/cases.json` were generated by and are
re-checked against actual upstream `get_urls`; three localhost CLI tests cover
ordering, stdin, comments, missing/empty files and flag precedence.

python3 tools/compare_batch.py --upstream /path/to/yt-dlp
