# Overwrite options

Exact official source target and unchanged baseline:
`897341241f2bfb2439fe0367f4c7c9ccd29a3828` (2026.08.19). No intervening
upstream commits; the global baseline is unchanged.

Inspected `options.py` `-w/--no-overwrites`, `--force-overwrites`/
`--yes-overwrites`, `--no-force-overwrites` and `-c/--continue` (1451–1470);
`__init__.py` (`--force-overwrites` implies `--no-continue`, 587) and the
`overwrites` parameter (841); `YoutubeDL.py` parameter normalization (776–784),
`report_file_already_downloaded`, `existing_file` (3323–3332),
`process_info`'s `existing_video_file` single/merged branches (3466–3590),
`_write_info_json` (4400–4421) and `_write_subtitles` (4447–4470); and
`downloader/common.py` `FileDownloader.download` (430–455). These also cover
`final_ext` converted candidates, `--no-part`/`--no-continue` resume,
description/link/thumbnail files and `--no-post-overwrites`, which are not
implemented here.

Implemented: three modes (`None` default, `-w` false, forced true; last flag
wins). Media: an existing regular file is "already downloaded" (default and
`-w`, via upstream's continue/no-overwrite checks) and recorded in the archive,
or deleted and replaced when forced. Info JSON (video and playlist) and
subtitles: replaced unless `-w`. Sidecars precede the media decision.

Native differences: existing media combined with audio/video processing or
subtitle embedding is an explicit error without `--force-overwrites`
(upstream reruns postprocessors); nonregular/dangling destinations are refused;
info JSON replacement is an atomic rename.

`tests/fixtures/overwrites/cases.json` holds 30 cases (six flag sets × five
existing-file states) generated by and re-checked against actual `parseOpts`
and `process_info` with only `HttpFD.real_download` stubbed. A localhost CLI
test replays every case; other CLI tests cover messages and archive records.
